OceanEyes — Sistema de Vigilancia Ciudadana del Mar

Fecha: 11 de octubre de 2026

1. Resumen Ejecutivo

Se ejecutó una prueba de estrés escalada sobre el gateway de registro municipal de OceanEyes, simulando 50, 500 y 5000 usuarios concurrentes.

Conclusión: El sistema soporta carga nominal (50-500 usuarios) sin degradación. A partir de 5000 usuarios colapsa por saturación TCP.

2. Marco Teórico

2.1 Tipos de Pruebas de Carga

Las pruebas se clasifican en: Smoke Test, Load Test, Stress Test, Soak Test. Esta prueba es un Load + Stress Test escalado.

2.2 ISO/IEC 25010

El estándar define: Performance, Scalability, Reliability. El sistema preserva performance en 50-500 usuarios pero falla en escalabilidad a 5000.

5. Análisis

5.1 Causa Raíz del Colapso

NO es un problema del código del Worker, sino de capacidad TCP local:

  • Windows limita a ~5000 puertos dinámicos
  • Wrangler local tiene backlog TCP finito (~128)
  • 87.9% de errores son "Connection refused", no errores de aplicación

6. Limitaciones

✗ Entorno local con emuladores (no producción)
✗ Una sola máquina JMeter
✗ Sin latencia de red real
✗ Tiempos absolutos 2-5× menores que producción

7. Conclusiones

  • Escalabilidad relativa excelente (50→500): 10× throughput, 20× latencia
  • El código del Worker es estable hasta 500 usuarios
  • Colapso a 5000 es artefacto del entorno, no fallo de código

8. Recomendaciones

  • Ejecutar con distributed JMeter (múltiples máquinas)
  • Replicar en staging Cloudflare Workers
  • Load test contra Firebase real (no emulador)
  • Implementar rate limiting en producción

Fin del informe • Análisis bajo ISO/IEC 25010 e ISO/IEC 29119
